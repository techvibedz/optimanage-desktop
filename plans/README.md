## Findings considered and rejected / deferred

- **`main.ts` is a 2956-line monolith** (split per domain): real tech debt, but a
  large, risky refactor that must wait until 001's tests exist. Deferred, not planned.
- **`local_` ID resolution via whole-JSON string substitution** (`syncManager.ts:370-378`):
  latent data-corruption risk, but low probability (ids are `local_<ms>_<rand>`).
  Worth a follow-up; not in the selected set. Add tests for it as part of 001 so a
  future fix is safe.
- **`backoffMs` 5-minute cap is dead code** (discovered during 001 execution):
  `Math.min(5*60_000, 1000 * Math.pow(2, Math.min(retries, 8)))` tops out at
  `2^8 = 256000ms` (~4.27 min), so the outer 5-min clamp never engages and the
  comment is wrong. Cosmetic — backoff tops out ~44s sooner than intended. Not
  planned; fix in passing if `syncManager.ts` is touched again.
- **Handlers trust `params.userId` from the renderer** instead of `currentUser.id`:
  low practical risk (the renderer only knows its own cuid) and fixing it fully means
  re-signing every handler. Documented in 003's maintenance notes as a follow-up.
